# 白羽实时回答与工具进度


## 执行阶段

1. 工具选择阶段保留原生 tool calling、参数校验、并行读取、写操作屏障和执行预算。工具事件立即转发；模型在需要工具时产生的中间正文不向用户展示。信息充分时只要求简短说明已经准备好回答。
2. 最终作答阶段关闭工具入口，使用当前用户问题、保留的上下文、工具证据及操作回执生成回答。Provider 产生安全正文增量后立即转发到 App 和网页。
3. 完成时仍由运行时补充真实操作回执和作品清单，提交会话，再发送最终结果。客户端替换正文进行校准，不能再次追加整篇回答。

当前模型接口是通用 Chat Completions，没有 Codex 的正文阶段标记；模型是否继续请求工具只能等一轮完成后确认。因此采用明确的最终作答阶段，比原循环多一次模型请求。原先最后一轮生成完整回答的请求改为简短的工具就绪响应，新增请求负责实际回答。这个选择保证流式内容来自最终作答阶段，但不承诺缩短总响应时间。

## 事件契约

| 事件 | 用途 |
| --- | --- |
| `progress` | 当前阶段：理解问题、整理上下文、核对结果、整理回答 |
| `tool_start` | 开始实际工具执行，带 `name`、`sequence`、`status`、自然语言 `text` |
| `tool_result` | 对应执行的结束状态，带 `sequence`、`outcome` 和自然语言 `text`；工具异常也归一到此事件 |
| `answer_start` | 开始或重建回答，清空本请求的旧草稿 |
| `delta` | 增量追加正文 |
| `done` | 已完成的权威结果；`answer` 替换正文，附属卡片与操作按原契约处理 |

工具名称到页面文案的映射集中在 `baiyu_agent/agents/progress.js`。页面显示“白羽正在搜索动漫”“白羽正在查询作品详情”等能力描述，不输出工具原始参数、错误栈或模型内部推理。失败、需要确认、结果不足分别显示；并行工具通过执行序号匹配，不能用最后一条进度代表所有工具。

## 中断与一致性

- 最终作答仍受原有运行超时、取消、上下文预算和正文长度限制。
- 流式过程中检查记忆版本；版本变化时撤回旧草稿，在原有执行预算内按新上下文重新规划。
- 最终作答拒绝新的原生工具调用，不能借此绕过工具执行预算。
- 已发布正文之后不重试整条模型流；异常交由原有失败或操作回执恢复路径处理。恢复结果开始前重置草稿。
- 已完成业务操作的回执独立保留，不会因回答中断而丢失。
- 最终阶段保留上下文裁剪的历史淘汰信息，供原有后续维护使用。
- App 回调校验请求与账户归属，网页校验账户与输出节点；新建对话后旧回调不能写入新对话。
- 增量期间只在阅读位置接近底部时跟随滚动，发送消息和打开历史仍主动定位到底部。

本地结果、恢复回执、模型未配置等完整结果直接发送，不通过延时拆字模拟模型流式生成。Provider 仍保留少量协议前缀安全缓冲，所以很短的回答可能一次显示；网络或上游代理自身聚合响应也会影响实际刷新频率。
