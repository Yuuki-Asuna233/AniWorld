# 运行数据

服务端默认将 SQLite 数据库保存为 `data/runtime/anime_user.db`。可通过 `ANIME_DB_PATH` 指向源码目录以外的持久化路径。

数据库保存账户、追番、观看记录、元数据、Agent 会话与记忆等运行状态；它不是可随意清理的构建缓存。数据库和相关运行文件不纳入 Git。

## 数据库使用边界

本项目使用 `sql.js`，每个进程持有完整内存快照，由 [DatabaseFileStore](../../apps/server/src/database/file-store.js) 管理单进程所有权、文件锁和落盘。

- 同一数据库只启动一个 API 实例，不使用 PM2 cluster。
- 独立元数据同步、RAG 建索引或 `rag:status` 脚本也会初始化数据库，需要先停止 API。
- 遇到锁异常先核实持有进程；不要在 API 正常运行时删除锁文件。
- 不要在服务仍持有内存快照时覆盖磁盘数据库。

## 备份与恢复

停服并确认数据已落盘后再复制数据库。若已启用独立 RAG 存储，还必须一同备份、恢复对应的 `anime_user.db.rag.db`；服务端记录了配对关系，仅关闭环境开关不能撤销已经完成的拆分。

初始化时可能创建 `.before-canonical.bak`、`.before-agent-context-v2.bak` 等迁移前快照。这些快照不等于定期备份，不保证含最新用户数据。

数据库备份之外，部署者还需分别保留私有配置、上传资源、发布包与客户端签名密钥。恢复操作应在停服状态下进行，再使用配套版本代码启动。
