# 番剧目录数据包

`anime-meta.v1.json` 是 `anime_meta` 表的目录快照，供首次部署导入。当前包含 **6,016 条**记录，其中 **2,687 条**已有中文名和 `oi_msg`。年份范围为 2010—2027，2027 年包含已公布的条目；并非每年、每部作品都有完整资料。

只有番剧 ID、名称、封面地址、评分、分类、开播日期和目录映射等字段。没有视频或封面文件，也没有账户、观看记录、追番、聊天、记忆、令牌和管理日志。资料来自 AniList 元数据及 OIAPI／本地维护的名称映射，不因随源码提供而改用代码许可证，来源的权利及使用条款仍适用。

## 首次导入

在仓库根目录执行，导入期间服务应保持停止：

```sh
npm ci
npm run setup:env
npm run data:import
npm start
```

已有服务先在运行 `npm start` 的终端按 Ctrl+C；PM2 用户使用实际进程名停止服务。不要删除数据库锁文件强行导入。

导入不会清空数据库。新番剧按 AniList ID 插入，已有番剧只补齐缺失值；后台编辑记录中修改过的字段会保留。导入前创建 `.before-catalog-import-时间戳.bak` 备份，写入在同一事务内完成，同时更新标题搜索索引和 RAG 索引队列。RAG 队列不等于自动调用模型，是否建索引由服务器配置决定。

重复导入不会覆盖已有评分、播出进度和资料，也不会导入快照中的动态下次播出时间。这些信息由运行中的同步维护。数据包只是目录，播放仍需在客户端选源；推荐和分类也会筛选中文名、映射和播出状态，展示数不会等于记录总数。

## 导出自己的目录

```sh
npm run data:export -- ./data/seed/my-catalog.json
```

导出只读取磁盘数据库快照，不会修改它；如果要包含最新操作，先正常停止服务。使用 `ANIME_DB_PATH` 时，导入和导出都会遵守该配置。导出文件仍要检查数据来源的再分发权限，不能据此直接公开运行数据库。

导入指定文件：

```sh
npm run data:import -- ./data/seed/my-catalog.json
```

JSON 顶层包含 `format`、`version`、`exportedAt`、`recordCount` 和 `records`。导入会先验证版本、字段、ID 和记录数，未知字段或重复 ID 会中止，不执行文件中的 SQL。
